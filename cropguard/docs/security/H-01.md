## Clave del cliente

`lib/core/network/supabase/supabase_client.dart:5` contiene una clave con formato publicable de Supabase; `:8` la entrega al SDK mediante `publishableKey`. Se verificó el tipo sin reproducir el valor. Se mantiene la configuración funcional del cliente y no se cambian endpoints ni credenciales.

Supabase permite incluir una clave publicable en un cliente móvil. Es diferente de `sb_secret` y del JWT legado con rol `service_role`, que son credenciales de servidor y pueden eludir RLS. Una clave publicable identifica a la aplicación; los permisos de los usuarios deben protegerse mediante sesión, RLS y autorización. **La revisión H-01 no acredita esos controles de autorización.** [Documentación oficial de API keys](https://supabase.com/docs/guides/getting-started/api-keys).

Mover configuración a `--dart-define` o a un JSON local facilita administrar entornos, pero los valores compilados en Flutter siguen siendo extraíbles. En este turno se conserva el cliente que usa la clave publicable correcta. Las nuevas exclusiones de configuración local previenen inclusiones accidentales; no convierten el cliente en un almacén de secretos privados.

El alcance es el contenido y el historial accesibles localmente. No se recuperaron objetos inalcanzables ni se consultó la visibilidad remota de los repositorios. **Rotación pendiente identificada: ninguna.** La presencia de la clave publicable en el cliente no justifica por sí sola rotar una credencial privada. El estado de RLS, los permisos sobre recursos y la protección de sesiones se revisan por separado.

No se repite la compilación ni la suite de aplicación porque no cambian fuentes, dependencias ni recursos de ejecución. Las comprobaciones de este hallazgo son las auditorías de secretos, la clasificación, la preservación de configuración, la exclusión de artefactos y la revisión del diff. Quedan pendientes la revisión del usuario y sus commits separados en ambos repositorios.
