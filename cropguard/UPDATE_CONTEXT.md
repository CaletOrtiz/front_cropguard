# Actualización de documentación y contexto del proyecto

Necesito que actualices el archivo `PROJECT_CONTEXT.md` existente para que refleje fielmente el estado actual del repositorio.

El objetivo es mantener este documento como fuente de contexto técnico para futuras sesiones de desarrollo con asistentes de IA.

## 1. Análisis de cambios

Antes de modificar el documento:

1. Examina el contenido actual de `PROJECT_CONTEXT.md`.
2. Analiza el estado actual del repositorio y su código fuente.
3. Identifica los archivos nuevos, modificados y eliminados.
4. Detecta cambios en la arquitectura, estructura, dependencias y funcionalidades.
5. Identifica modificaciones en modelos, entidades, tablas, relaciones, endpoints, servicios y flujos de información.
6. Comprueba si las funcionalidades documentadas siguen correspondiendo con la implementación actual.

## 2. Actualización del contexto

Actualiza las secciones correspondientes de `PROJECT_CONTEXT.md` según los cambios encontrados.

Debes mantener documentados:

- Descripción y objetivos del proyecto.
- Stack tecnológico y dependencias.
- Arquitectura y organización del código.
- Estructura de carpetas y archivos.
- Módulos y funcionalidades.
- Modelos, entidades y base de datos.
- APIs, endpoints y servicios.
- Integraciones externas.
- Flujos de información.
- Configuraciones y variables de entorno.
- Seguridad y autenticación.
- Instalación y ejecución.
- Pruebas y validaciones.
- Funcionalidades implementadas, parciales y pendientes.
- Consideraciones importantes para futuros desarrolladores.

## 3. Reglas para conservar la documentación

- No sobrescribas el documento desde cero si ya contiene información válida.
- Conserva las secciones que no hayan sufrido cambios.
- Modifica únicamente la información que haya quedado desactualizada.
- Incorpora las nuevas funcionalidades y componentes.
- Elimina o corrige información que ya no corresponda al código actual.
- Actualiza los diagramas Mermaid cuando los cambios afecten la arquitectura o los flujos.
- Mantén la estructura y el nivel de detalle de la documentación existente.
- Evita duplicaciones y contradicciones.
- No inventes información ni asumas funcionalidades que no estén implementadas.

## 4. Registro de cambios

Al final del documento, incorpora o actualiza una sección llamada `Historial de actualizaciones`.

Registra:

- Fecha de actualización.
- Resumen de los cambios documentados.
- Nuevos componentes o funcionalidades.
- Componentes modificados o eliminados.
- Secciones de documentación afectadas.

No registres cambios que no puedas verificar en el repositorio.

## 5. Restricciones

- No modifiques código fuente.
- No modifiques configuraciones del proyecto.
- No alteres archivos diferentes de `PROJECT_CONTEXT.md`.
- No expongas credenciales, tokens ni claves privadas.
- No elimines información técnica que siga siendo válida.

## Resultado esperado

Actualiza directamente el archivo `PROJECT_CONTEXT.md` existente.

El documento debe representar el estado real y actualizado del repositorio, conservando el contexto histórico que siga siendo relevante y sirviendo como referencia para futuras sesiones de desarrollo con IA.

Al finalizar, presenta un resumen de las modificaciones realizadas y las secciones actualizadas.
